# Proposal

## Why

The A/B image currently requires a floating content-addressed nixpkgs evaluation so that the copied `closureInfo.registration` can be trusted to describe the shipped store bytes. That makes the appliance build depend on experimental CA behavior across evaluation, builders, caches, garbage collection and overlay stores; upstream realisation and rebuild failures now block routine image verification. The required product invariant is narrower: the store database and store filesystem shipped for a slot must describe the same immutable snapshot.

## What Changes

- Build the supported appliance closure with ordinary input-addressed nixpkgs evaluation; remove the `contentAddressedByDefault` assertion and CA-specific package-set workarounds from the test pipeline.
- Replace the independent store-tree and registered-record dump artifacts with one paired slot-store snapshot. Its store tree preserves every closure path faithfully, and its lower database is generated by Nix from that exact tree through a scratch local store.
- Use `nix-store --register-validity` without `--hash-given` so Nix computes each staged path's NAR hash and size from the staged bytes, then export the scratch database with `nix-store --dump-db`. Keep the existing `nix-store --load-db` runtime artifact and ESP delivery contract unchanged.
- Keep path/reference topology from Nix's exported reference graph and validate that the resulting records form the complete toplevel closure. Do not implement a second NAR serializer, store-path renaming scheme or content-derived runtime store.
- **BREAKING**: Appliance images no longer guarantee CA path identities or require `ca-derivations` on image builders, appliance overlay daemons and runner environments. New image and runtime coverage uses input-addressed closures and ordinary binary-cache behavior.
- Preserve the existing symlink-faithful imaging, lower-only delta installation, runner clone/overlay seeding, OTA and rollback behavior under input addressing.
- Implement and accept this change directly on `main`; later backporting into `slot-scoped-overlay-uppers` is a separate integration activity.
- No deployed CA appliances are in scope. Do not add CA-to-IA migration, mixed-addressing rollback or preservation of existing CA upper state to this change.

## Capabilities

### New Capabilities

(none)

### Modified Capabilities

- `ab-ota`: the lower-store database becomes a Nix-generated description of the exact staged store snapshot rather than verbatim registered records from a mandatory CA evaluation.
- `overlay-nix`: runtime overlay operation is specified and verified over input-addressed lower closures without requiring CA derivation support.
- `runner`: appliance runner environments consume the snapshot-derived lower database without a mandatory CA feature or CA closure assumption.

## Impact

- `modules/ab-image/`: pair store staging and database generation, remove the CA evaluation assertion and retain the existing image/ESP artifact interfaces.
- `modules/overlay-nix/`, `modules/runner/`: remove CA-only daemon/environment requirements while retaining local-overlay and read-only-store functionality.
- `flake.nix`, `tests/`: replace the shared CA package set and overrides with ordinary package sets; add focused snapshot/database coherence checks and run affected pure and KVM suites with input addressing.
- `doc/user_guide/`, `doc/technical_details/`, `README.md` where its repository map changes: document snapshot-derived records, build-time cost, trust boundary and the absence of a CA migration path.
- No consumer option rename or new public topology/store API is introduced. Store paths and binary-cache identities of newly built appliance closures change from CA to input-addressed identities.
